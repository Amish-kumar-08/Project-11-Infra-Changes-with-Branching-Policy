# Project 11: Infrastructure Changes with Branching Policy

## Overview

Implemented a Git branching strategy to manage infrastructure changes safely and collaboratively. Created a feature branch, made infrastructure-related changes, and submitted a Pull Request (PR) for review before merging the changes into the main branch.

## Objectives

- Understand Git branching strategies.
- Create and manage feature branches.
- Make infrastructure changes in a separate branch.
- Commit and push changes to GitHub.
- Create a Pull Request for code review.
- Merge approved changes into the main branch.

## Technologies Used

- Git
- GitHub
- GitHub Pull Requests
- PowerShell
- Infrastructure as Code (IaC) concepts

## Branching Strategy

This project follows a simple feature branching workflow:

1. `main` – Contains the stable version of the project.
2. `feature/infra-update` – Used for making infrastructure changes.

## Implementation Steps

1. Created a GitHub repository.
2. Cloned the repository to the local machine.
3. Created initial infrastructure documentation.
4. Created a feature branch named `feature/infra-update`.
5. Made infrastructure-related changes.
6. Committed and pushed the changes to GitHub.
7. Created a Pull Request from the feature branch to the main branch.
8. Reviewed the Pull Request.
9. Merged the Pull Request into the main branch.
